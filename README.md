## Результаты замера Debug vs Release
| Режим | Запуск 1 | Запуск 2 | Запуск 3 | Запуск 4 | Запуск 5 | Минимум |
| ------- | -------: | -------: | -------: | -------: | -------: | ------: |
| Debug | 1827 | 1819 | 1806 | 1811 | 1811 | 1806 |
| Release | 246 | 252 | 254 | 244 | 257 | 244 |

В моём эксперименте Release оказался быстрее/медленнее Debug примерно в
7 раз.

Что я обнаружил при сравнении IL:

1. Очевидное различие в размере кода. 
2. в Debug присутствуют инструкций cgt и ceq, которых нет в Release.
3. количество IL-инструкций в методе Add() изменилось с 11 до 4.

1. IL — это независимый промежуточный код, который нужен для переноса программы на любые процессоры, где JIT-компилятор превратит его в машинные инструкции.
2. .dll можно декомпилировать, так как внутри неё хранятся читаемые IL-инструкции и подробные метаданные о структуре кода, а не машинный код.
3. В Release-версии IL-код короче, из него удалены пустые операции nop, лишние переменные .locals init и лишние сохранения в память stloc/ldloc.
4. Release быстрее, потому что компилятор включает оптимизации и убирает отладочную информацию, перегружающую Debug-версию.
5. Строковый пароль не защищен, так как все текстовые строки хранятся в .dll в открытом, незашифрованном виде и легко читаются через HEX-редактор.
